# Архитектура и системный дизайн ContextSync

В этом документе описаны архитектурные принципы, взаимодействие компонентов, потоки данных и модель безопасности сервиса синхронизации контекста **ContextSync**.

---

## 1. Высокоуровневая архитектура

## 2. Разбор компонентов

### 2.1 Транспортный уровень FastMCP (`src/mcp_server.py`)
- **Протокол**: Спецификация Model Context Protocol (MCP) 2024-11-05.
- **Транспорт**: Server-Sent Events (SSE) и `stdio` (через мост mcp-remote).
  - `GET /sse`: Клиенты инициируют SSE-поток. Сервер создает `session_id` и возвращает адрес для сообщений `/messages?session_id=<UUID>`.
  - `POST /messages?session_id=<UUID>`: Клиенты отправляют стандартные запросы JSON-RPC 2.0 (`initialize`, `tools/list`, `tools/call`, `ping`). Ответы отправляются в SSE-поток.
- **Инструменты контекста**:
  - `context_save`: Векторизация и сохранение сниппетов.
  - `context_search`: Семантический векторный поиск по косинусному расстоянию.
  - `context_get`: Извлечение документа по UUID или заголовку.
  - `context_list`: Просмотр списка недавних документов.
  - `context_delete`: Удаление устаревших контекстов.

### 2.2 Векторный движок (`src/embeddings.py`)
- **Модель**: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` через `fastembed`.
- **Среда выполнения**: ONNX Runtime на CPU с поддержкой многопоточности.
- **Характеристики**:
  - Размерность вектора: 384 числа с плавающей точкой.
  - Потребление памяти: ~130 МБ RAM.
  - Скорость: ~8–15 мс на 512 токенов на современном CPU.
  - Полная автономность: не требует ключей OpenAI или внешнего интернета.

### 2.3 Разрешение конфликтов на уровне фактов (FLCR) (`src/facts.py`)
При совместной работе агентов стандартные хранилища документов страдают от перезаписи контекста. Движок FLCR вводит атомарные факты:
- **Атомарный триплет**: Любой параметр системы хранится как `(project, entity, attribute) -> value` с инкрементом версии `version` и булевым статусом `is_active`.
- **Стратегии разрешения конфликтов**:
  - **LWW (Last-Write-Wins)**: Автоматически деактивирует старый факт (`is_active = False`) с записью `superseded_by`, создавая неизменяемую историю развития архитектуры проекта.
  - **Authority Policy (Иерархия авторитетности)**: `User (100)` > `Architect (80)` > `Agent (50)` > `Worker (10)`. Изменения от агентов с низким приоритетом не могут стереть решение человека и помечаются `conflict_flag = True` для ручного разрешения.
- **Генерация Fact Truth-Table**: Активные утвержденные факты автоматически компилируются в Markdown-таблицу и вставляются в `AGENTS.md` и `CLAUDE.md`.

### 2.4 Автономный демон фоновой синхронизации (`src/syncer/daemon.py`)
Демон связывает статичные правила проектов с активностью агентов в реальном времени:
1. **Обнаружение рабочих областей**: Сканирует локальные директории проектов VS Code, Cursor, JetBrains, Codex CLI и Antigravity.
2. **Парсинг истории сессий**: Извлекает недавние действия из локальных баз SQLite и JSONL-логов.
3. **Синтез дайджеста**: Формирует сводку последних архитектурных решений, активных агентов и Таблицу Фактов.
4. **Безопасная инъекция маркеров**: Обновляет файлы `AGENTS.md`, `CLAUDE.md` и `.cursorrules` строго между тегами `<!-- CONTEXT-SYNC-START -->` и `<!-- CONTEXT-SYNC-END -->`, полностью сохраняя персональные промпты пользователя.

## 3. Модель безопасности и сеть

- **Аутентификация Bearer-токеном**:
  Все REST-эндпоинты и соединения MCP защищены токеном через заголовок `Authorization: Bearer <TOKEN>` или параметр URL `?token=<TOKEN>`.
- **Сетевой периметр**:
  - Порт приложения: `8200` (для исключения коллизий с Portainer).
  - Порт PostgreSQL: `5445` (для исключения коллизий со стандартным Postgres 5432).
  - Для доступа через интернет рекомендуется использовать Cloudflare Tunnel, Tailscale или обратный прокси Caddy с TLS.
